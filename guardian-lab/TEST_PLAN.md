## Deployment produksi dengan Ansible: pemeriksaan tertunda

Prasyarat: persetujuan terpisah untuk build/runtime/browser, host uji Linux amd64 dengan Docker Compose 2.32.2+, kedua repository dan perubahan Ansible yang cocok, registry uji, database MySQL terisolasi, input sintetis serta fixture OTP. Jangan memakai database atau credential produksi. Konfigurasi dan urutan aktivasi mengikuti [runbook deployment](ai-agent-docs/deployment.md#integrasi-ansible-dan-github-actions).

- [ ] **PROD-CAP: Kapasitas:** periksa `SANDBOX_MAX_SESSIONS=1` pada deployment produksi, default tanpa variabel sebanyak tiga, dan nilai 2/3 pada host uji yang memadai. Sesi yang melampaui kapasitas ditolak, satu sesi per akun tetap berlaku, dan nilai 0/4/pecahan/non-angka menggagalkan startup tanpa membuat container sesi.

- [ ] **PROD-01: Image web:** build stage `runner` tanpa database/secret produksi. Pastikan Node native menjalankan standalone, aset publik/Sharp tersedia, Prisma CLI/client/engine tersedia tanpa unduhan saat runtime, Java/JADX lolos verifikasi checksum, user non-root dapat memakai tmpfs dan cache pada root filesystem read-only. Public app URL cocok dengan deployment; tidak ada `.env` lokal di image.
- [ ] **PROD-02: Migrasi:** pada database baru dan database dengan data, jalankan job `docker/app/migrate.sh` dari image yang akan dipasang. Migrasi diterapkan sekali dan seed Academy berulang tidak menimpa kuis yang diedit. Tidak ada demo user, `db push`, reset atau training. Simulasikan kegagalan migrasi; web lama tidak diganti dan deployment gagal.
- [ ] **PROD-03: Model:** image AI memasang artifact resmi melalui installer/checksum asli. Health menunjukkan model available, `mode=shadow`, `production_ready=false`. ML-only deploy mempertahankan image web/broker/browser/egress dan sesi web; model unavailable tetap menghasilkan UNAVAILABLE tanpa skor/risk band pengganti, sementara web tersedia.
- [ ] **PROD-04: Proxy dan akun:** periksa HTTPS, Origin form, cookie secure, login/OTP dengan fixture dan batas upload APK sampai 50 MiB melalui Nginx. API broker, model, VNC, Squid dan socket Docker tidak dapat dijangkau publik. Header IP tidak dipercaya selama `AUTH_TRUST_PROXY=false`; jangan mengaktifkannya tanpa memverifikasi overwrite header oleh proxy.
- [ ] **PROD-05: Sandbox:** mulai sesi pada origin stream yang satu site dengan web; periksa tiket/iframe/WebSocket, kapasitas tiga global/satu per akun, deadline 180 detik, auto-destroy serta rekonsiliasi setelah broker restart. Verifikasi browser tanpa internet langsung, proxy menolak alamat lokal/metadata termasuk redirect/DNS, serta karantina APK tetap berbatas ukuran dan tanpa host download mount. Tidak ada URL tiket/target pada log stream.
- [ ] **PROD-06: Rilis dan pemulihan:** kedua workflow hanya deploy dari `main` setelah gate diaktifkan. Keempat image web harus selesai sebelum pembaruan; bootstrap manual dengan `deploy=false` tidak menghubungi VPS. Uji dua deploy bersamaan, kegagalan pull/readiness, pin digest, snapshot sebelumnya, penerapan kembali rilis terakhir dan rollback image tanpa rollback database. Host key salah menggagalkan SSH.
- [ ] **PROD-07: Lifecycle dan cleanup:** restart stack/host mempertahankan database, cache, referensi versi dan kemampuan membuka sesi baru. Dalam host uji terisolasi, jalankan cleanup terjadwal tanpa sesi aktif; keeper mencegah image browser/egress serta jaringan egress terhapus. Pengulangan Ansible mempertahankan pin CI dan tidak mengubah credential aplikasi lain.

## Compose development dan pembaruan kode: pemeriksaan tertunda

Prasyarat: persetujuan cakupan konfigurasi/build/runtime/browser yang dipilih, Docker Engine Linux atau Docker Desktop dengan Linux containers, Compose 2.32.2+, dua checkout berdampingan, serta `.env` berisi kunci sesi/broker valid. Gunakan daemon dan volume development terisolasi tanpa broker Guardian lain berjalan, input sintetis, serta fixture OTP bila diperlukan. Jangan memakai database atau kredensial produksi.

- [ ] **DEV-01: Konfigurasi:** bila disetujui, jalankan `docker compose --env-file .env -f docker/docker-compose.dev.yml config --quiet`. Pastikan include sandbox dan overlay development dapat di-resolve, stage aplikasi `development`, environment `NODE_ENV=development`, alamat layanan memakai `db`/`ml`/`broker`, MySQL tidak memiliki port host, dan browser/proxy menjadi layanan persiapan yang keluar sukses sebelum broker dimulai. Semua script/dokumen memakai nama Compose baru; stage `runner` tetap production standalone.
- [ ] **DEV-02: Bootstrap:** jalankan satu perintah `up --build --watch` pada lingkungan uji yang disetujui. Build image layanan ML toleran terhadap fluktuasi jaringan PyPI (`PIP_DEFAULT_TIMEOUT=120`, `PIP_RETRIES=5`). Database sehat lebih dahulu; Prisma generate/migrate deploy dan seed Academy selesai sebelum Next dev melayani port 3000. Model sehat memuat artifact resmi sebagai user non-root, dan broker menemukan image browser/proxy. Login dengan akun uji atau seed demo opsional melalui `exec app bun run db:seed`; tidak ada OTP nyata tanpa izin. Restart/down/up mempertahankan data volume dan tidak menyentuh database host. Kegagalan migrasi menghentikan startup tanpa reset atau `db push`.
- [ ] **DEV-03: Fast Refresh:** setelah izin browser, ubah komponen, CSS, handler API dan aset publik pada host ketika Watch aktif. Perubahan disinkronkan ke `/app` dan tampil tanpa build production atau restart manual; penambahan/penghapusan berkas juga terbaca. Tidak ada source bind mount yang menimpa dependency Linux. `node_modules`, `.next`, `.tools`, `.env*` dan Git host tidak disalin oleh Watch. User non-root tetap dapat menulis source dan cache Next di container.
- [ ] **DEV-04: Rebuild aplikasi:** perubahan pasangan package/lockfile, Prisma/migrasi, toolchain APK, Dockerfile/entrypoint dan `.dockerignore` memicu rebuild aplikasi. Dependency/Prisma/JADX mengikuti versi dan checksum konfigurasi baru; migrasi yang tersedia diterapkan dengan data tetap ada. Package/lockfile tidak cocok atau build gagal terlihat pada keluaran Watch dan tidak diklaim telah diterapkan. Perubahan schema tanpa migrasi tidak memicu pembuatan atau reset database otomatis.
- [ ] **DEV-05: Model dan sandbox:** perubahan source runtime model yang sah beserta manifest memicu rebuild dan tetap memerlukan parity artifact nyata pada cakupan Python yang disetujui. Guard salah menolak build; amati bahwa container lama bisa tetap berjalan dan tidak boleh diklaim memakai source baru. Dataset, binary/environment lokal dan notebook tidak ikut konteks/pemantauan model. Source broker memicu rebuild/restart dengan rekonsiliasi sesi; perubahan image browser/egress dipakai sesi baru. Verifikasi isolasi, deadline 180 detik, karantina dan model unavailable tetap sesuai kontrak.
- [ ] **DEV-06: Konfigurasi dan lifecycle:** ubah `.env` atau file Compose lalu hentikan dan jalankan ulang perintah yang sama; environment/config baru dimuat. Perubahan source ketika Watch mati ikut image pada `up --build --watch` berikutnya. Ctrl+C menghentikan foreground; `down` mempertahankan volume. Alias `docker:dev`/`docker:up` menjalankan Watch, `docker:build` membangun target development, dan `docker:down` tidak menghapus data. Pemeriksaan build/test/lint/typecheck/browser tetap menunggu izin; tidak ada kode test baru pada perubahan konfigurasi ini.
- [ ] **DEV-07: Makefile:** setelah izin pemeriksaan, gunakan GNU Make untuk memastikan `make`/`make help` hanya menampilkan bantuan tanpa Docker atau `.env`; pilih dry-run untuk memeriksa pemetaan dev/up, down, build/logs dengan dan tanpa `SERVICE`, ps, shell, config dan target database. Dari direktori induk, `make -f guardian-lab/Makefile ...` tetap memakai `.env` serta Compose milik repo web. Pada cakupan runtime yang disetujui, `make dev` memakai Watch, `make down` mempertahankan volume, `make config` tidak mencetak rahasia dan target database tetap mengarah ke container development. Makefile tidak disalin ke image/source container dan tidak memicu pembaruan aplikasi. Tidak ada target reset atau penghapusan volume otomatis.
- [ ] **DEV-08: Bootstrap key:** setelah izin, jalankan generator pada salinan repo/fixture environment terisolasi, tanpa stack Compose aktif. `.env` yang belum ada dibuat dari template; kedua key kosong/placeholder menjadi nilai berbeda berformat 64 hex dari 32 byte CSPRNG, dengan permission `0600` dan ownership user pemanggil. Konfigurasi lain, komentar, CRLF/LF, export/quote dan literal multiline yang berisi nama key tetap utuh. Key custom valid dipertahankan dan pengulangan default tidak mengubah `.env`. Fallback `AUTH_SECRET` valid dipertahankan sebagai canonical session key. Tidak ada secret pada stdout/stderr, argumen proses, image, atau request jaringan generator.
- [ ] **DEV-09: Seleksi dan rotasi:** pada fixture yang disetujui, `KEY=SESSION_SECRET`/`KEY=SANDBOX_BROKER_KEY` hanya mengubah pilihan itu; `FORCE=1` mengganti key terpilih secara eksplisit. Key/force tidak dikenal, duplikasi, custom value pendek, format invalid, symlink, konflik penulisan dan permission error tidak merusak atau menimpa `.env` asal. Dua proses generator tidak menulis bersamaan; file sementara normal dibersihkan dan interupsi meninggalkan file privat yang dapat dipulihkan manual. `FONNTE_TOKEN`, credential provider, `.env.example` dan file lain tidak berubah. Dengan cakupan runtime disetujui, restart stack setelah generator dan pastikan key dibaca website serta broker; token lama setelah rotasi mengikuti perilaku autentikasi yang berlaku. Tidak ada kode test baru atau eksekusi generator pada environment pengguna hanya untuk verifikasi otomatis.
- [ ] **DEV-10: Resolver Prisma/Turbopack:** setelah izin build/runtime, hentikan Watch lama dan mulai `make run`; alias run/dev/up harus menjalankan konfigurasi yang sama. Periksa stage development memakai image Node.js 22, dependency tetap diinstal dengan Bun, dan proses Next/worker memakai Node native, bukan `bun-node-fallback-bin/node`. Prisma Client ter-generate dan alias external Turbopack di `.next/dev/node_modules` mengarah ke dependency dalam image. Setelah izin browser, buka login, register, landing dan halaman dengan sesi/database; error `@prisma/client-<hash>` tidak muncul. Uji Fast Refresh, pemanggilan API, Sharp/JADX dan reload setelah rebuild dependency agar perubahan runtime tidak mengubah perilaku fitur. Data volume MySQL serta key environment dipertahankan; tidak ada penghapusan database/cache host, alias hash buatan, downgrade bundler, atau penggantian import Prisma sebagai solusi.
- [ ] **DEV-11: Origin form di Docker:** setelah izin pemeriksaan yang dipilih, verifikasi helper origin dengan URL internal `http://0.0.0.0:3000` dan `http://[::]:3000`, serta normalisasi `localhost`. Host `localhost:3000`, `127.0.0.1:3000`, dan `[::1]:3000` diterima hanya bila Origin cocok persis dengan Host, protokol dan port. Origin dari situs lain, pertukaran localhost/IP, protokol/port berbeda dan literal `null` tetap 403. Origin loopback dengan Host invalid atau port Host berbeda dari URL internal juga ditolak; `X-Forwarded-Host`/`X-Forwarded-Proto` tidak dapat mengganti hasil helper. Sertakan regresi URL publik dengan Origin yang sesuai serta perilaku GET/HEAD/OPTIONS dan request tanpa Origin yang sudah berlaku. Setelah izin browser/runtime, jalankan `make run` dengan Watch, buka `http://localhost:3000`, kirim form login dengan akun fixture dan form autentikasi lain dengan gateway OTP fixture, lalu mutasi fitur dari akun terverifikasi. Submit mencapai validasi/otorisasi normal tanpa pesan penolakan Origin; tidak ada OTP nyata atau data pribadi asli. Pastikan perubahan helper disinkronkan Watch dan penolakan lintas situs tetap 403. Cakupan dapat memperluas `tests/auth/origin.test.ts` hanya setelah izin penulisan test; jangan membuat kode test atau mengeksekusinya pada tugas perbaikan ini.

## Bedah APK dengan JADX & DeepSeek AI: pemeriksaan tertunda

Prasyarat: persetujuan eksplisit untuk cakupan pemeriksaan yang dipilih; implementasi ini tidak menjalankan test/lint/typecheck/build/browser otomatis. Gunakan akun USER/ADMIN uji dan berkas APK sintetis/uji lokal (seperti fixture `tests/fixtures/apk/hello.apk`). Jangan mengunggah berkas yang memuat data pribadi asli atau malware berbahaya aktif tanpa lingkungan terisolasi.

- [ ] **APK-AI-01: Ekstraksi Statis & Dekompilasi JADX:** unggah berkas APK valid melalui panel uploader di `/apk`. Periksa dekompilasi JADX mengekstrak AndroidManifest.xml, membaca package name, label aplikasi, versi, min/target SDK, dan daftar izin tanpa memasang berkas di perangkat. Periksa penolakan berkas non-APK menghasilkan status FAILED (HTTP 422).
- [ ] **APK-AI-02: Sanitasi PII & Integrasi DeepSeek:** verifikasi metadata sebelum diproses melewati PII Scrubber (nama berkas, nama paket, teks URL, dan cuplikan kode). Saat `DEEPSEEK_API_KEY` terkonfigurasi, pastikan DeepSeek Chat (`deepseek-chat`) memberikan analisis terstruktur dalam format JSON valid (risk_level, risk_score 0–100, scam_category, human_friendly_summary, red_flags, dan emergency_action_plan).
- [ ] **APK-AI-03: Fallback Heuristik Deterministik:** uji dengan `DEEPSEEK_API_KEY` kosong atau terputus jaringan. Pastikan sistem secara otomatis beralih ke `buildApkHeuristicAnalysis` tanpa menimbulkan error 500. Izin SMS (RECEIVE_SMS/READ_SMS/SEND_SMS) menghasilkan MALWARE (skor 88–98); izin aksesibilitas/overlay menghasilkan MALWARE (skor 90–92); izin instal paket menghasilkan DANGEROUS (skor 75–80); dan aplikasi tanpa izin berlebih menghasilkan SAFE (skor 10–25).
- [ ] **APK-AI-04: Transisi Status COMPLETED & Tampilan Dual-Mode:** pastikan investigasi APK berhasil bertransisi ke status `COMPLETED` dengan `analysisSource="DEEPSEEK_STATIC_APK"`. Hasil tampil di `/apk?investigation=<id>`: Mode Manusia menyajikan Skor Risiko (`ThreatScoreGauge`), Kedok Penipu Terbongkar (`KedokCard`), serta Panel Statis JADX (`ApkStaticPanel`). Mode Teknis menyajikan cuplikan kode Java terdekompilasi (`ApkStaticTechnical`) dan bukti teknis tersimpan (`GeekViewPanel`).
- [ ] **APK-AI-05: Integrasi Share Card & Komunitas:** dari halaman hasil APK berstatus `COMPLETED`, klik "Buat Guardian Share Card"; pastikan kartu memuat nama berkas APK, skor risiko, dan temuan trik penipuan. Pastikan tombol "Ajukan ke komunitas" berfungsi dan data teknis (permissions, c2Endpoints) tervalidasi pada skema komunitas.
- [ ] **APK-AI-06: Progress Bar Interaktif & Estimasi Tahapan Realtime:** saat tombol "Periksa APK" ditekan (`pending=true`), pastikan `ApkProgressCard` muncul dengan angka persentase bergerak naik (0% s.d. 100%), bar gradien cyan-teal dengan shimmer glow, dan teks tahapan dinamis (1/4 verifikasi, 2/4 dekompilasi, 3/4 audit izin, 4/4 DeepSeek AI). Pastikan transisi ke 100% saat respons diterima.

## Pemeriksaan runtime sandbox

Jalankan hanya bila disetujui dan runtime uji siap:

- `node --env-file=.env scripts/verify-sandbox.mjs`: stream HTTP/WebSocket, autentikasi, egress, penolakan tujuan lokal/metadata, serta stop/cleanup.

## Prasyarat eksekusi

- Sesuaikan lingkungan melalui [deployment.md](./ai-agent-docs/deployment.md) hanya setelah cakupan pengujian disetujui. Jangan mengubah `.env` atau data aplikasi untuk sekadar menyiapkan QA.
- Tes database memakai [tests/setup.ts](./tests/setup.ts) dari [bunfig.toml](./bunfig.toml): MySQL sementara berprefix `guardian_lab_test_`, migrasi dan fixture terisolasi, lalu cleanup. `maxConcurrency = 1` menjaga ekstraksi JADX serta skenario constraint tetap deterministik. Jangan menjalankan seed demo atau reset pada database aplikasi.
- Jika Turbopack gagal membuat worker karena pembatasan lingkungan, gunakan fallback resmi `bunx next build --webpack` setelah persetujuan build; jangan mengubah `.env` atau mematikan SSR hanya untuk melewati pemeriksaan.
- APK memakai Java/JADX terverifikasi dan fixture jinak pada `tests/fixtures/apk/`; jangan gunakan malware hidup. Tes Bun sandbox memakai provider fixture; pemeriksaan container nyata terpisah.
- Pengujian Share Card/komunitas yang memerlukan hasil lengkap memakai fixture terkontrol pada database uji, atau hasil layanan v6 hanya bila cakupan integrasi nyata disetujui. Mock clipboard/share agar tidak mengirim pesan kepada orang lain.
- Setelah eksekusi yang disetujui, tandai hanya hasil yang benar-benar diperiksa, tulis kegagalan singkat yang masih perlu ditangani, dan hapus kasus selesai yang tidak lagi relevan. Jangan menambah arsip log panjang.
